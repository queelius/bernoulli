\section{What is a Cipher Map?}
\label{sec:what-is-cipher-map}

The first sixteen chapters analyzed noisy computation on cleartext: a
Bloom filter errs because the structure is small, a classifier because
the world is hard, a sketch because the stream is large, and in each
case the user accepts the error to save space or time. This chapter
applies the same machinery to a different setting. The data is
encrypted, the computation runs on the encrypted form, and only a holder
of a secret key can read the result. Bloom filters and noisy classifiers
reappear, but now their false positives and false negatives carry a
second role alongside the operational one: the bounded error is also
what keeps the plaintext hidden from the party doing the computation.

\subsection*{The abstraction}

Begin with a plaintext function $f : X \to Y$. In the cleartext setting
a user holds $x$, applies $f$, and reads $f(x)$. The cipher-map setting
introduces a split. A holder of $x$ (the \emph{client}) wants $f(x)$ but
will not give $x$ to the machine computing it. The client encrypts $x$
under $\mathsf{Enc}$, sends the ciphertext to a \emph{server}, and asks
the server to compute on $\mathsf{Enc}(x)$ something the client can
decrypt to (something close to) $f(x)$. The server never sees $x$, and
never sees $f(x)$ directly; what it returns is an encryption of an
output the client decrypts with $\mathsf{Dec}$. The companion map that
operates on the encrypted representations is the cipher map\index{cipher map}.

\begin{definition}[Cipher map]
\label{def:cipher-map}
Let $f : X \to Y$ be a plaintext function, $\mathsf{Enc} : X \to
\mathsf{Enc}(X)$ an encryption map with decryption $\mathsf{Dec} :
\mathsf{Enc}(Y) \to Y$. A \emph{cipher map} for $f$ is a function
$\tilde f : \mathsf{Enc}(X) \to \mathsf{Enc}(Y)$ on the encrypted
representations such that, for $x \in X$,
\[
  \Pr\left[\,\mathsf{Dec}(\tilde f(\mathsf{Enc}(x))) = f(x)\,\right]
  \;\ge\; 1 - \fnrate
\]
when $f(x)$ is a positive output, and the probability of a spurious
$y \ne f(x)$ on the negative case is at most $\fprate$. The pair
$(\fprate, \fnrate)$ is the cipher map's \emph{error profile}, in the
Bernoulli sense of \Cref{sec:quantifying-noise}.
\end{definition}

The cipher map operates entirely on the encrypted domain; decryption
happens client-side after the encrypted output returns; and the rates
$\fprate, \fnrate$ are exactly those the framework has spent sixteen
chapters analyzing, so there is no new probabilistic machinery. The error
also bears on what an observer can infer: a false positive is a report
that does not correspond to a real member, so it can mask real ones. But
the rates do not by themselves determine confidentiality. A cipher map
with positive error can still leak through what it does not randomize
(equal queries producing equal encodings, access patterns, result sizes),
and a map with zero error can hide everything if its outputs are never
revealed to the observer, as in fully homomorphic encryption.
Confidentiality needs a stated observation model and adversary on top of
the error model; \Cref{sec:bernoulli-error-model} treats the error side
and \Cref{sec:trapdoor-paradigm} and \Cref{sec:maximizing-confidentiality}
the leakage side.

Several of the properties asked of cipher maps below have long
cryptographic histories, and the chapter borrows rather than originates
them. Making each plaintext value correspond to many possible encodings,
so that encoding frequencies flatten, is homophonic substitution
\parencite{jendal-kuhn-massey-1989}\index{homophonic substitution}; making
every decoding attempt, even with a wrong key, return a plausible-looking
value is the distribution-transforming encoder of honey encryption
\parencite{juels-ristenpart-2014}\index{honey encryption}; storing a key-value map so
that the structure hides which keys it encodes, and non-keys decode to
values that look like stored ones when the stored values are random, is
the oblivious key-value store
\parencite{garimella-et-al-2021,bienstock-et-al-2023}\index{oblivious key-value store};
computing a function through key-dependent lookup tables is white-box
cryptography \parencite{chow-et-al-2002}; hiding a point
function behind a hash that reveals only equality is point-function
obfuscation \parencite{canetti-1997,lynn-prabhakaran-sahai-2004}; and
encrypting so that a chosen property stays testable is property-preserving
encryption \parencite{pandey-rouselakis-2012}.

\subsection*{Why approximate is acceptable}

The exact alternative exists. Fully homomorphic encryption (FHE),
introduced by Gentry in 2009 and refined by the BFV, BGV, and CKKS
schemes, gives an $\tilde f$ with $\fprate = \fnrate = 0$ for any
computable $f$. The catch is cost: FHE ciphertexts run kilobytes or more
per encrypted value and homomorphic operations are many orders of
magnitude slower than the plaintext computation they replace. Cipher maps trade error for practicality, just as
the cleartext approximate-set literature trades Bloom false positives for
memory. A filter-based cipher map for membership needs at least
$\log_2(1/\fprate)$ bits per element (the bound of chapter~8, due to
\textcite{carter-et-al-1978}), about $1.44$ times that as a Bloom
filter, runs in constant time, and gives a tunable false-positive rate. \Cref{sec:fhe-sidebar} works the comparison in detail.

\subsection*{The trapdoor key}

What distinguishes a cipher map from any other noisy function is the
\emph{trapdoor key}\index{trapdoor computing}: a secret that recovers $f(x)$ from
$\tilde f(\mathsf{Enc}(x))$. The client holds it; the server does not.
Without the trapdoor the server sees only opaque bit patterns and cannot
tell meaningful queries from filler, real outputs from noise, or one
plaintext from another; with it the client decrypts to within the
$(\fprate, \fnrate)$ bounds. Three properties make the key worth its
name: it is \emph{short} (constant length, not growing with the data),
\emph{necessary} (under the construction's security assumption, no
efficient computation without it recovers the plaintext), and
\emph{sufficient} (a key holder decrypts at about the per-call cost of a
plaintext evaluation). The three distinguish a cipher
map from a generic encryption (which lacks sufficiency) and from a
generic noisy function (which lacks the first two).

\subsection*{Three example cipher maps}

Three cipher maps recur in this chapter and chapter~18, sketched here to
ground \Cref{sec:bernoulli-error-model}.

\textbf{Encrypted set membership.} For a plaintext set $A \subset X$ the
client wants $f_A(x) = \mathbf{1}[x \in A]$ without revealing $A$. It
builds a Bloom filter on $A$ whose probe positions come from a keyed
pseudorandom function (the key is the trapdoor) and gives the bit array
to the server; to query, it sends the $k$ keyed positions for $x$, an
encoding $\mathsf{Enc}(x)$ the server cannot invert, and the server tests
those bits. This is the secure index of \textcite{goh-2003}\index{secure index}. The
returned bit is correct on negatives with probability at least $1 -
\fprate$ and always correct on positives ($\fnrate = 0$), the one-sided
error of the Bloom construction.

\textbf{Encrypted equality test.} For $f_=(x, y) = \mathbf{1}[x = y]$,
deterministic encryption makes identical plaintexts encrypt identically,
so ciphertext equality coincides with plaintext equality and $\fprate =
\fnrate = 0$. The cost is a known leak: an adversary watching many tests
builds the plaintext distribution from ciphertext frequencies. This is a
cipher map with no Bernoulli error but nonzero information leak, a
reminder that the rates are not the only confidentiality knob.

\textbf{Encrypted ordering.} For $f_{\le}(x, y) = \mathbf{1}[x \le y]$,
order-preserving encryption preserves plaintext order in the ciphertext
encoding, so the server compares ciphertexts directly at $\fprate =
\fnrate = 0$, leaking the entire plaintext ranking, a larger leak than
equality.

The three span the landscape. The Bloom-based map sits at the
high-$\fprate$, zero-$\fnrate$ corner of the perfect-filter line of
\Cref{sec:perfect-filter-line}; the equality and ordering maps sit at the
zero-zero corner but pay their confidentiality cost through structural
leakage rather than rate. The $(\fprate, \fnrate)$ machinery describes the error of all three; it
says nothing about the structural leakage of the second and third, which
needs a leakage model of its own (frequency and order leakage are the
standard ones). The PPV/NPV machinery of \Cref{def:ppv} gives one
confidentiality measure for the first case under a stated observation
model (\Cref{sec:maximizing-confidentiality}), not a general one.
