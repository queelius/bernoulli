\section{CountMin}
\label{sec:countmin}

A data stream presents items $x_1, \ldots, x_n$ from a universe $\Universe$
with repetition. For $a \in \Universe$, write $f_a = |\{i : x_i = a\}|$ for its
true frequency and $F = \sum_b f_b = n$ for the stream length. The
frequency-estimation query reports an estimate $\hat f_a$ of $f_a$ in a small
structure of size polylogarithmic in $F$, with a tunable error bound.

\subsection*{The construction}

Fix a width $w$ and depth $d$ and pick $d$ hash functions $h_1, \ldots, h_d :
\Universe \to \{1, \ldots, w\}$ from a pairwise-independent family
($\Prob{h_i(a) = u,\, h_i(b) = v} = 1/w^2$ for distinct $a, b$), which is
cheaper than the full independence the Bloom filter assumed
(\Cref{def:bloom-filter}).

\begin{definition}[CountMin sketch]
\label{def:countmin}
The \emph{CountMin sketch} of parameters $(w, d)$ is a $d \times w$ integer
table $C$, initialized to zero, with $d$ hashes, and two operations:
\textsc{Update}$(a)$ increments $C[i][h_i(a)]$ for each $i$, and
\textsc{Query}$(a)$ returns $\hat f_a = \min_i C[i][h_i(a)]$.
\end{definition}

\begin{algorithm}[ht]
  \caption{CountMin update and query}
  \label{alg:countmin-update-query}
  \SetKwProg{func}{procedure}{}{}
  \SetKwProg{fn}{function}{}{}
  \func{\textsc{Update}($a$)}{
    \For{$i \gets 1$ \KwTo $d$}{$C[i][h_i(a)] \gets C[i][h_i(a)] + 1$\;}
  }
  \BlankLine
  \fn{\textsc{Query}($a$)}{
    $m \gets \infty$\;
    \For{$i \gets 1$ \KwTo $d$}{\lIf{$C[i][h_i(a)] < m$}{$m \gets C[i][h_i(a)]$}}
    \Return $m$\;
  }
\end{algorithm}

Both operations run in $O(d)$ time, independent of $F$ and $|\Universe|$, in
$d \cdot w$ counters. Each cell $C[i][h_i(a)]$ holds $f_a$ plus a non-negative
collision mass from other items hashing to the same cell, so $C[i][h_i(a)] \ge
f_a$ for every $i$ and $\hat f_a = \min_i C[i][h_i(a)] \ge f_a$. The estimate
never under-shoots, the count-valued analogue of the Bloom filter's deterministic
no-false-negatives property; the minimum across $d$ independent rows attenuates
the collision noise, since the estimate exceeds the truth only when every row
collides with a heavy item.

\subsection*{The error bound}

\begin{theorem}[CountMin bound]
\label{thm:countmin-bound}
With width $w = \lceil e/\epsilon \rceil$ and depth $d = \lceil \ln(1/\delta)
\rceil$, for any $a$ the estimate satisfies $f_a \le \hat f_a \le f_a + \epsilon
F$ with probability at least $1 - \delta$.
\end{theorem}

\begin{proof}
Fix $a$ and a row $i$. Write the collision mass $X_i = \sum_{b \neq a} f_b\,
\mathbf{1}[h_i(b) = h_i(a)] \ge 0$, so $C[i][h_i(a)] = f_a + X_i$. By pairwise
independence each $b$ collides with probability $1/w$, so $\Expect{X_i} =
(F - f_a)/w \le F/w$. Markov's inequality gives $\Prob{X_i \ge \epsilon F} \le
\Expect{X_i}/(\epsilon F) \le 1/(\epsilon w) \le 1/e$, the last step using
$w \ge e/\epsilon$. The $d$ rows use independent hashes, and $\hat f_a >
f_a + \epsilon F$ only if every row overshoots, so $\Prob{\hat f_a > f_a +
\epsilon F} \le (1/e)^d \le \delta$ since $d \ge \ln(1/\delta)$. The lower
bound is the deterministic argument above.
\end{proof}

The bound is additive in $F$, not in $f_a$: heavy hitters with $f_a$ comparable
to $F$ are estimated at small \emph{relative} error, while light items with
$f_a \ll \epsilon F$ are washed out. CountMin is the sketch for finding which
items are heavy, not for the counts of light ones. The space is $d \cdot w =
\lceil \ln(1/\delta) \rceil \lceil e/\epsilon \rceil = O\big((1/\epsilon)
\ln(1/\delta)\big)$ counters, logarithmic in the failure probability and
inverse in the additive error (\textcite{cormode-muthukrishnan-2005}).

\begin{remark}[Expected overshoot]
\label{rem:expected-overshoot}
The high-probability bound has a tighter expectation behind it. A single row's
overshoot has mean $\Expect{X_i} = (F - f_a)/w$, and at the design width
$w = \lceil e/\epsilon \rceil$ this is $\le F/w = \epsilon F / e$, a factor $e$
below the headline slack $\epsilon F$. The factor $e$ is exactly the Markov
slack the proof pays to turn a mean into a tail bound; the reported minimum sits
below even this per-row mean.
\end{remark}

\subsection*{The $\Bernoulli{T}$ type and merging}

CountMin instantiates \Cref{ch:approximate-functions} with $T = \mathbb{N}$: its
channel $Q$ (\Cref{def:n-ary-channel}) has rows indexed by the true count, and
the deterministic $\hat f_a \ge f_a$ makes $Q$ \emph{upper triangular}, the
count-valued analogue of the Bloom filter's one-sided membership matrix. Each
row concentrates near the diagonal, with at most a $\delta$ fraction of mass
more than $\epsilon F$ columns to the right. Two sketches built on disjoint
substreams with the same parameters and hashes merge by entry-wise addition,
$(C_1 \oplus C_2)[i][j] = C_1[i][j] + C_2[i][j]$, which is exactly the sketch of
the concatenated stream because \textsc{Update} only increments and addition
commutes; the same $(\epsilon, \delta)$ bound holds at the combined $F$. Sharing
the hash family is what keeps the merge a single correct sketch rather than a
doubling of the failure probability, an instance of the
\Cref{thm:n-ary-kronecker} composition.

\subsection*{Worked example}

Take $w = 10$, $d = 5$, so the achieved parameters are $\epsilon = e/w \approx
0.272$ (additive bound $\epsilon F = 0.272\,F$) and $\delta = e^{-d} \approx
0.0067$. On a stream of $F = 1000$ items with a heavy item $f_{a_1} = 410$, the
expected per-row overshoot is $(F - f_{a_1})/w = 590/10 = 59$, so each row
reports near $469$ and the minimum across five rows falls below it; a typical
realization returns $\hat f_{a_1} = 432$, an overshoot of $22$, well inside the
bound $\epsilon F = 272$. For a light item with $f = 4$, the expected per-row
overshoot is $99.6$, and the estimate, though correctly bounded by $4 + 272$, is
uninformative about the true count. This is the heavy-hitter design point:
heavy items tight relative to their own count, light items only up to the
additive slack. \Cref{sec:hyperloglog} turns to the complementary question of
how many \emph{distinct} items a stream contains.
