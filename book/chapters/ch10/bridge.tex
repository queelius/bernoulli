\section{Bridge}
\label{sec:ch10-bridge}

Three sketches\index{sketch}, one skeleton, differing in output type and
channel shape. CountMin\index{Count-Min sketch} (\Cref{sec:countmin}) is the
frequency sketch: $T = \mathbb{N}$,
one-sided, an upper-triangular $Q$ with tail $\Prob{\hat f_a \ge f_a + \epsilon
F} \le \delta$ (\Cref{thm:countmin-bound}). HyperLogLog\index{HyperLogLog} (\Cref{sec:hyperloglog})
is the cardinality sketch: $T = \mathbb{N}$, two-sided and log-normal, with
relative error $1.04/\sqrt{m}$ (\Cref{prop:hyperloglog-error}) setting the band
width. MinHash\index{MinHash} (\Cref{sec:minhash-lsh}) is the similarity sketch: $T = [0,1]$,
binomial rows, Hoeffding-controlled at signature length $k$
(\Cref{prop:minhash-error}). Each comes with a construction, a row-by-row error
bound on $Q$, and a merge rule.

The merge rules share a structure this chapter notes but does not axiomatize.
Merging CountMin tables is entry-wise \emph{addition}, HyperLogLog registers
entry-wise \emph{maximum}, MinHash signatures (forming the union signature)
entry-wise \emph{minimum}; each is associative, commutative, and has an identity
(the zero table, the zero register bank, the all-$\infty$ signature), and each
merge of sketches built with shared hashes equals the sketch of the combined
input. That is the \emph{mergeability}\index{mergeable summary} property studied systematically by
\textcite{agarwal-et-al-2013}. It is a property of each construction, a
commutative monoid on summaries, and it does not follow from the channel
reading: the channel describes one query's error, while a merge acts on the
stored summary. \Cref{ch:algebra-types} places the sketches in the same type
vocabulary as the rest of Part~III without deriving their merge rules from it.
Before that, \Cref{ch:randomized-algorithms} turns from streaming summaries to
randomized algorithms, where a one-sided Monte Carlo
procedure\index{Monte Carlo algorithm} is a
$\Bernoulli{\{\text{accept}, \text{reject}\}}$ value and amplification by
repetition is independent runs on one input followed by an aggregator (AND, OR,
or majority), and \Cref{ch:approximate-relations} lifts the framework from
functions to relations for join and multi-attribute queries.
