\section{The Optimality Question}
\label{sec:optimality-question}

Chapter~8 closed Part~II with a contrast it could not resolve. The
entropy floor\index{space lower bound!approximate membership}
(\Cref{thm:entropy-floor}) certified that some FNR-zero
representation could in principle reach $-\log_2 \fprate$ bits per
element, but it exhibited none; the standard Bloom filter, the only
concrete FNR-zero scheme on the table\index{Bloom filter}, sat a fixed multiplicative
factor above that floor. The bound was diagnostic, not constructive.
This chapter supplies constructions: an explicit FNR-zero approximate
set that meets the floor up to lower-order terms at an exponential
build cost, and a practical one that replaces the Bloom filter's
multiplicative overhead with an additive constant.

\subsection*{The gap}

\Cref{thm:entropy-floor} of \Cref{sec:entropy-floor} states that any
FNR-zero approximate-set representation with false-positive rate at
most $\fprate$ requires
\[
  L / n \;\ge\; -\log_2 \fprate \;+\; o(1)
\]
bits per element in the asymptotic regime $N \gg n$, $\fprate$ fixed.
The argument is a counting bound: $2^L$ representations must cover
$\binom{N}{n}$ possible target sets, and each representation describes
at most $\binom{|A_R|}{n}$ true sets inside its accepted set, forcing
$L$ to grow linearly in $n \log_2(1/\fprate)$.

\Cref{prop:bloom-overhead} of \Cref{sec:bloom-gap} computes the Bloom
filter's budget from \Cref{def:bloom-filter}: at the optimal hash count
$k^* = (m/n)\ln 2$, the per-element cost is
\[
  m / n \;=\; \log_2(1/\fprate) \cdot \log_2 e,
\]
or $\log_2 e \approx 1.4427$ times the floor, a constant independent of
$\fprate$\index{Bloom filter!space overhead}. The overhead traces to a structural choice: $k$ independent
hashes write into a flat shared bit array, and the analysis maximizes
per-bit entropy by tuning the array to half occupancy. Half-occupancy
is the wrong target. Bits should pay for the discrimination the
structure performs, not for the encoding's internal balance.

\subsection*{The constructive question}

\Cref{sec:bloom-gap} isolated three Bloom design choices, $k$
independent hashes, a flat shared bit array, and a conjunction query,
and observed that closing the gap requires abandoning at least one.
A construction that answers the question needs five properties:
FNR-zero by construction, so it stays on the perfect-filter axis with
the Bloom filter; an FPR provably at most $\fprate$; a per-element
budget matching $-\log_2 \fprate$ up to a lower-order correction; a
query running in time comparable to Bloom's; and a build that finishes
in time polynomial in $n$. The floor, which goes back to
\textcite{carter-et-al-1978}, bounds the third property from below. The
question is which explicit constructions meet which of the five, and at
what price.

\subsection*{The answer in sketch}

Two constructions answer it from opposite ends, and the chapter treats
both.

The \emph{Bernoulli hash function} (BHF)\index{Bernoulli hash function}
abandons stored per-element structure altogether. It fixes an
acceptance set of density $\fprate$ in the output range of a hash
function and searches for a single \emph{salt}\index{seed search}
under which every member of $A$ hashes into the acceptance set; the
salt is the whole representation, and a query hashes $x$ with the salt
and tests acceptance. Each member is accepted with probability
$\fprate$ under a given salt, so a salt succeeds with probability
$\fprate^n$, and the first success has an index whose binary length
is $n \log_2(1/\fprate) + O(1)$ in expectation. The BHF therefore meets
the floor up to lower-order terms, with no integer rounding, and its
query is a single hash evaluation. What it gives up is the fifth
property: the expected number of salts tried is $\fprate^{-n}$,
exponential in $n$. This is single-seed search, the mechanism that
modern perfect-hashing constructions apply to small buckets
\parencite{esposito-graf-vigna-2020,lehmann-sanders-walzer-2024,lehmann-et-al-2025}.

The \emph{perfect hash filter}\index{perfect hash filter} keeps the
build polynomial. A minimal perfect hash $\phi : A \to [n]$ addresses a
table of $r$-bit fingerprints with $r = \lceil -\log_2 \fprate
\rceil$, and a query compares the stored fingerprint with the query's
own. It meets every property except the third exactly: the
fingerprints cost $r$ bits per element, but a minimal perfect hash
cannot cost less than $\log_2 e \approx 1.44$ bits per element
\parencite{fredman-komlos-1984}, so the total sits a constant
\emph{additive} amount above the floor, against the Bloom filter's
multiplicative factor. The pairing of a minimal perfect hash with
fingerprints, and its $\log_2 e$ overhead, are described by
\textcite[Sec.~1]{dietzfelbinger-pagh-2008}. Retrieval structures close
the remaining gap to a factor $1 + \delta$ at linear build time
(\Cref{sec:space-analysis}).

\Cref{sec:space-analysis} its expected size and the perfect hash
filter's budget, \Cref{sec:fpr-analysis} the false-positive analysis of
