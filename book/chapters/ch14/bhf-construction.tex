\section{The BHF Construction}
\label{sec:bhf-construction}

The Bernoulli hash function stores no table.\index{Bernoulli hash function} It stores one salt, chosen
so that a fixed acceptance rule happens to accept every member of the
designated set, and it answers a query by applying the same rule to the
query. This section states the construction, proves that it has no false
negatives, computes the probability that a candidate salt succeeds, and
works one example small enough to build. \Cref{sec:space-analysis}
computes the expected size, and \Cref{sec:construction-time} the build
cost that the size is bought with.

\subsection*{Acceptance predicate and salt}

Fix a finite universe $\Universe$, a designated set $A \subseteq
\Universe$ with $|A| = n$, a modulus $N \ge 1$, and a threshold $t \in
\{0, 1, \ldots, N - 1\}$. Let $h : \Universe \times \{0, 1\}^* \to \{0,
1, \ldots, N - 1\}$ be a hash of an element and a bit-string \emph{salt},
modeled as a random oracle\index{random oracle}: its values at distinct pairs $(x, b)$ are
independent and uniform on $\{0, \ldots, N - 1\}$. An element $x$ is
\emph{accepted}\index{threshold!acceptance} under salt $b$ when
\begin{equation}
\label{eq:bhf-accept}
  h(x, b) \;\le\; t,
\end{equation}
an event of probability
\[
  \fprate \;=\; \frac{t + 1}{N}
\]
for any fixed pair. The acceptance set $\{0, \ldots, t\}$ is fixed
before any salt is examined; it is part of the specification, not
something read off the data. The admissible rates form the lattice
$\{j / N : 1 \le j \le N\}$, as fine as the modulus allows.

Enumerate bit strings in order of length and then lexicographically,
$b_1$ the empty string, $b_2 = 0$, $b_3 = 1$, $b_4 = 00$, and so on, so that $b_q$ has length $\lfloor \log_2 q \rfloor$. A salt
$b$ is \emph{valid} for $A$ when every member is accepted under it.

\begin{definition}[Bernoulli hash function]
\label{def:bhf}
The \emph{Bernoulli hash function} (BHF)\index{Bernoulli hash function} for $A$ with parameters $(N,
t)$ is the triple $(N, t, b^{*})$, where $b^{*} = b_Q$ and $Q$ is the
least index $q$ for which $b_q$ is valid for $A$. Its membership query is
\[
  \textsc{Query}(x) \;=\; \top \;\text{ iff }\; h(x, b^{*}) \le t.
\]
\end{definition}

The definition follows the source manuscript
\parencite{towell-bernoulli-hash-function}, which calls this the
threshold predicate; its equality predicate, which lets the first member
fix a target value $h_0$ and requires the others to hit it, is the same
construction with the acceptance set chosen after one hash and stored
alongside the salt, and it costs the same number of bits in total.\index{seed search}
\Cref{alg:bhf-insert-query} writes the construction out.

\begin{algorithm}[ht]
  \caption{BHF construction (salt search) and query}
  \label{alg:bhf-insert-query}
  \SetKwProg{func}{procedure}{}{}
  \SetKwProg{fn}{function}{}{}

  \func{\textsc{Build}($A$, $N$, $t$)}{
    \For{$q = 1, 2, 3, \ldots$}{
      $b \gets b_q$\;
      \lIf{$h(a, b) \le t$ for every $a \in A$}{\Return $(N, t, b)$}
    }
  }
  \BlankLine
  \fn{\textsc{Query}($x$)}{
    \lIf{$h(x, b^{*}) \le t$}{\Return $\top$}
    \Return $\bot$\;
  }
\end{algorithm}

A failed salt is usually discarded early: the scan over $A$ stops at the
first rejected member, which arrives after an expected at most $1/(1 -
\fprate)$ hash evaluations. The query is one hash evaluation and one
integer comparison, the cheapest query in Part~IV.

\subsection*{The false-negative rate is exactly zero}

Let $x \in A$. The build returned $b^{*}$ only because $h(a, b^{*}) \le t$
held for every $a \in A$, in particular for $x$, and the query
recomputes the same value $h(x, b^{*})$. Hence $\textsc{Query}(x) = \top$
for every member and every parameter setting, and\index{false-negative rate}
\[
  \fnrate \;=\; 0.
\]
The BHF sits on the FNR-zero arm of the perfect-filter line\index{perfect filter line}\index{one-sided error}, with the
Bloom filter. Its only failure mode is a non-member whose hash under
$b^{*}$ happens to fall in the acceptance set, at probability exactly
$\fprate$ (\Cref{prop:bhf-fpr}).

\subsection*{Success probability of a salt}

Under the random-oracle model the $n$ values $h(a, b)$, $a \in A$, are
independent for a fixed salt, each in the acceptance set with
probability $\fprate$, so a candidate salt is valid with probability
\begin{equation}
\label{eq:bhf-success}
  s \;=\; \fprate^{\,n}.
\end{equation}
Distinct salts give independent trials, so the index $Q$ of the first
valid salt is geometric with parameter $s$: $\Prob{Q = q} = (1 - s)^{q-1}
s$ and $\Expect{Q} = 1/s = \fprate^{-n}$. Everything about the BHF's cost
follows from this one fact. Its size is the length of $b_Q$, about
$\log_2 Q \approx n \log_2(1/\fprate)$ bits, which is the floor; its
build is $Q$ trials, about $2^{n \log_2(1/\fprate)}$, which is
exponential. Each bit of the representation is paid for with a doubling
of the search.

The construction extends to maps without change of mechanism, which is
why the manuscript treats sets as the zero-length-value case. For a map
$A \to \{0, 1\}^{*}$ whose values have encodings of mean length $\mu$, a
second hash of $(x, b)$ must also reproduce each member's encoded value,
so a salt is valid with probability $\fprate^{n} 2^{-n\mu}$ and the
expected representation grows to $n(\log_2(1/\fprate) + \mu)$ bits, the
space-accuracy scale for approximate maps (the maps themselves are the
subject of \Cref{ch:approximate-functions}). The rest of the chapter
stays with sets.

\subsection*{A worked example}

Take $n = 8$ and $\fprate = 1/4$ ($N = 4$, $t = 0$). A salt is valid with
probability $s = 4^{-8} = 2^{-16}$, so the build tries $2^{16} = 65{,}536$
salts on average, a fraction of a second. The returned salt has expected
length $\Expect{\lfloor \log_2 Q \rfloor} \approx 14.7$ bits
(\Cref{thm:bhf-optimality} gives the exact series), about $1.83$ bits per
element against the floor's $-\log_2(1/4) = 2$; the deficit is the
constant slack of the theorem, which the few bits needed to record $N$,
$t$, and the salt's length more than repay. A Bloom filter at the same
rate spends $2 \log_2 e \approx 2.89$ bits per element. The same
arithmetic at the chapter's usual operating point, $n = 1000$ and
$\fprate = 0.01$, gives $s = 10^{-2000}$: the BHF's size is still the
floor, about $6644$ bits, and its build is out of reach.
\Cref{sec:construction-time} returns to what that means in practice.
