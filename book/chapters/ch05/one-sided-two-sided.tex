\section{One-Sided vs Two-Sided Approximate Sets}
\label{sec:one-sided-two-sided}

The Bloom filter has one error rate exactly zero, by construction rather
than tuning. That is one shape an approximate set can take; others force
the false-positive rate to zero on a designated set, or allow both rates to
be positive. The shapes are not interchangeable, and the distinction
organizes the constructions of \Cref{ch:set-composition},
\Cref{ch:optimal-bernoulli-sets}, and \Cref{ch:perfect-hash-filters}.

\begin{definition}[One-sided and two-sided approximate sets]
\label{def:one-sided}
An approximate set $\ASet{A}$ with rates $(\fprate, \fnrate)$ is
\emph{one-sided in FNR} (FNR-zero) if $\fnrate = 0 < \fprate$; \emph{one-sided
in FPR} (FPR-zero) if $\fprate = 0 < \fnrate$; and \emph{two-sided} if both
rates are positive\index{one-sided error}\index{two-sided error}. The Bloom
filter (\Cref{def:bloom-filter}) is FNR-zero, and so is a minimal perfect
hash with one stored fingerprint per element (the perfect hash filter of
\Cref{def:phf}); the rank-table filter of \Cref{ch:perfect-hash-filters} is
FPR-zero, but only in a restricted query model.
\end{definition}

The name tracks the rate that is zero. A one-sided set sits on a coordinate
axis of the rate square $[0,1]^2$; a two-sided set in its interior; the
origin $\fprate = \fnrate = 0$ is the exact set, excluded as not
approximate. The Z-channel\index{channel!Z-channel} of \Cref{def:z-channel} is the per-query analog,
and the one-sided property is its per-set lift.

\subsection*{Why FNR-zero is the natural default}

The Bloom filter's FNR-zero property came for free from monotonicity: the
insert primitive only sets bits, so a query for an inserted item always
reads ones. Any structure on a monotone insert-only primitive shares it,
which is why summaries over append-only logs and hash-keyed sketches are
FNR-zero for the same structural reason. Forcing the opposite asymmetry is
harder. Making $\fprate = 0$ requires the structure to reject every
non-member, that is, to certify membership; a stored copy of the set does
this, at a cost of about $\log_2 |\Universe|$ bits per element, which is
the space an approximate set exists to save. A perfect hash with one
fingerprint per element does not certify: a member always finds its own
fingerprint (the structure is FNR-zero, like the Bloom filter), while a
non-member may still collide with the fingerprint stored at its slot.
\Cref{ch:perfect-hash-filters} reaches $\fprate = 0$ only by restricting the
query model so that a non-member cannot present the value it would need to
collide. The set must be known up front and updates are expensive; those
costs buy certainty in the positive direction.

\subsection*{Safety versus space}

One-sidedness is valuable because one direction of the answer is exact: a
Bloom filter's $\bot$ is certain (the element is definitely absent), so a
cache can skip a lookup or a spell-checker can pass a known word without
follow-up. An FPR-zero filter has the dual guarantee, a certain $\top$.
Two-sided sets give up the certain direction\index{Bloom filter!two-sided variants}.
Sometimes this is a side effect rather than a goal: a \emph{counting} Bloom
filter \parencite{fan-et-al-2000} replaces bits with small counters to
support deletion, at roughly four times the space, and a counter overflow, or
the deletion of an item that was never inserted, can later zero a counter a
member still needs, introducing a positive $\fnrate$
\parencite{guo-et-al-2010}. Other designs trade false positives for false
negatives on purpose: the retouched Bloom filter clears selected bits to
remove chosen false positives \parencite{donnet-baynat-friedman-2006}, and
the generalized Bloom filter sets and resets bits so that both rates are
positive by design \parencite{laufer-velloso-duarte-2011}.

The size of the trade is calculable. By \Cref{eq:bloom-optimal-k} a Bloom
filter at $\fprate = 0.01$, $\fnrate = 0$ needs $m \approx 1.44\,n
\log_2(1/\fprate) \approx 9.6\,n$ bits.
\Cref{ch:information-bounds} gives the classical floor for any FNR-zero set
at the same $\fprate$, about $n\log_2(1/\fprate) \approx 6.64\,n$ bits, so
the Bloom filter pays the familiar factor $\log_2 e \approx 1.44$. Static
constructions from the retrieval literature close most of that gap
efficiently (\Cref{sec:bloom-gap}); the Bernoulli Hash Function of
\Cref{ch:optimal-bernoulli-sets} meets the floor in space, but only at a
construction cost exponential in $n$. A two-sided set
does not escape the floor by much: tolerating false negatives on a fraction
$\fnrate$ of the members lowers the leading-order cost only to about
$(1 - \fnrate)\,n\log_2(1/\fprate)$ bits (\Cref{prop:two-sided-floor}, after
\textcite{pagh-rodler-2001}), so giving up the certain $\bot$ saves at most
about $\fnrate \log_2(1/\fprate)$ bits per element.

\subsection*{The perfect filter line}

The rate plane $(\fprate, \fnrate) \in [0,1]^2$ parameterizes every
approximate set. The one-sided sets occupy the two axes, $\{\fnrate = 0\}$
and $\{\fprate = 0\}$; we call their union the \emph{perfect filter
line}\index{perfect filter line},
each axis a one-dimensional locus with one rate-degree of freedom. Two-sided
sets fill the interior; the exact set is the origin.

The line constrains composition. \Cref{ch:set-composition} derives the
union, intersection, complement, and difference of Bernoulli sets and shows:
\begin{itemize}
  \item the union and the intersection of two FNR-zero sets are FNR-zero;
  \item the complement swaps the axes, sending FNR-zero to FPR-zero;
  \item the difference of two sets on the same axis is two-sided, so it
    leaves the line.
\end{itemize}
By the complement symmetry the FPR-zero axis obeys the same rules, so the
algebra of the line is symmetric. The asymmetry between the two axes is
constructive, not algebraic: FNR-zero comes for free from monotone insertion,
while FPR-zero needs a certificate. \Cref{sec:bridge-to-sets} previewed the
per-element union and intersection rates; \Cref{ch:set-composition} derives
them in full. \Cref{ch:information-bounds} and
\Cref{ch:optimal-bernoulli-sets} then take up the FNR-zero axis (its floor
and a construction at it), and \Cref{ch:perfect-hash-filters} the FPR-zero
axis and the price of certifying a subset exactly.
