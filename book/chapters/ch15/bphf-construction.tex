\section{The BPHF Construction}
\label{sec:bphf-construction}

\Cref{sec:bhf-to-bphf} set the goal: a structure on the FPR-zero axis,
mirroring the way the perfect hash filter sits on the FNR-zero axis.
The plan keeps the minimal perfect hash $\phi : A \to [n]$ and replaces
the fingerprint table with a rank table the query verifies against the
candidate's own rank. The construction is short; the honest accounting
of what it does and does not deliver is the heart of the chapter,
because the rank table alone does not flip the error axis, and seeing
why reveals the asymmetry between the two arms of the perfect-filter
line.

\subsection*{The two ingredients}

Fix a finite universe $\Universe$ and a designated set $A \subseteq
\Universe$ with $|A| = n$.

\smallskip
\noindent\emph{(i) The perfect hash $\phi$.} The same minimal perfect hash
\[
  \phi \;:\; A \;\longrightarrow\; [n], \qquad [n] = \{1, 2, \ldots, n\},
\]
that the perfect hash filter of \Cref{def:phf} uses: an injection on $A$,
hence a bijection onto the addressing range, constructed at build time
from $A$ and extended to all of $\Universe$. Its build and storage costs
are the perfect hash filter's (\Cref{sec:space-time-analysis}). The BPHF
reuses it without modification.

\smallskip
\noindent\emph{(ii) The rank table $R$ and assignment $\rho$.} A
\emph{rank table} $R : [n] \to \{0, 1\}^r$ of $n$ slots, each of width
\begin{equation}
\label{eq:bphf-r}
  r \;=\; \lceil \log_2 n \rceil,
\end{equation}
the smallest integer with $2^r \ge n$. It is populated by a \emph{rank
assignment} $\rho : A \to \{0, 1, \ldots, n-1\}$ giving each member a
distinct integer, from a position in a sorted ordering, a relevance
score discretized to $n$ buckets, or external metadata. Distinctness of
the ranks is what fixes $r$ at $\lceil \log_2 n \rceil$: it takes that
many bits to label $n$ elements apart.

Where the perfect hash filter compared a stored fingerprint $g(a)$
against the candidate's $g(x)$, the BPHF compares a stored rank $\rho(a)$ against the
candidate's $\rho(x)$. The substitution is one line of pseudocode.
Whether it changes the error analysis is the question the rest of the
section answers, and the answer is more subtle than the symmetry of the
picture suggests.

\subsection*{Construction and query}

Given $A$, $\phi$, and $\rho$, the table is built in one pass:
\begin{equation}
\label{eq:bphf-build}
  \text{for each } a \in A: \quad R[\phi(a)] \;\coloneqq\; \rho(a),
\end{equation}
writing each slot exactly once by bijectivity of $\phi$, so the table is
fully populated.

\begin{definition}[Bernoulli Perfect Hash Filter]
\label{def:bphf}
The \emph{Bernoulli Perfect Hash Filter} (BPHF) for a designated set $A$
with parameters $\phi$, $\rho$, and $r = \lceil \log_2 n \rceil$ is the
pair $(\phi, R)$ together with the membership query
\[
  \textsc{Query}(x) \;=\; \top \;\text{ iff }\; R[\phi(x)] = \rho(x).
\]
After the build pass \eqref{eq:bphf-build}, $x \mapsto \textsc{Query}(x)$
is the membership report of the approximate set $\ASet{A}$.
\end{definition}

The definition has the shape of \Cref{def:phf}: a perfect-hash
addressing function, a per-slot value, and a query that reads one slot
and compares it to a computed value. The only change is which value is
stored, a uniform fingerprint $g$ for the perfect hash filter, an
application-chosen rank $\rho$ for the BPHF. \Cref{alg:bphf-build-query} writes it out.

\begin{algorithm}[ht]
  \caption{BPHF construction and query}
  \label{alg:bphf-build-query}
  \SetKwInOut{Input}{input}
  \SetKwInOut{Output}{output}
  \SetKwProg{func}{procedure}{}{}
  \SetKwProg{fn}{function}{}{}

  \func{\textsc{Build}($A$, $\rho$)}{
    construct perfect hash $\phi : A \to [n]$\;
    allocate rank table $R$ of size $n$, each slot $r$ bits\;
    \For{each $a \in A$}{
      $R[\phi(a)] \gets \rho(a)$\;
    }
    \Return $(\phi, R)$\;
  }
  \BlankLine
  \fn{\textsc{Query}($x$)}{
    $i \gets \phi(x)$\;
    $v \gets \rho(x)$\;
    \lIf{$R[i] = v$}{\Return $\top$}
    \Return $\bot$\;
  }
\end{algorithm}

Against the perfect hash filter's pseudocode
(\Cref{alg:phf-build-query}), the only changed line substitutes $\rho$
for $g$ in the value compared. The two
algorithms share their performance profile. Whether they share their
error profile is the question, and it needs care.

\subsection*{What the bare construction delivers}

Read the algorithm directly. For a member $a \in A$, bijectivity sends
$a$ to a slot written by $a$ alone, where the build stored $\rho(a)$; the
member recomputes $\rho(a)$, reads its own slot, and matches. The match
always succeeds, so $\fnrate = 0$. Even two members with equal ranks
would not interfere, because $\phi$ sends them to different slots and
each reads back the rank it wrote.

For a non-member $x \notin A$, the extended hash sends $x$ to a slot
$\phi(x) = \phi(a^{*})$ owned by some member $a^{*}$, holding
$\rho(a^{*})$. The query accepts $x$ exactly when the recomputed
$\rho(x)$ equals $\rho(a^{*})$. If $\rho$ behaves like a uniform $r$-bit
hash, the two agree with probability $2^{-r}$, so $\fprate = 2^{-r}$,
exactly the fingerprint-collision probability of \Cref{prop:phf-fpr}.
The bare BPHF, queried over the full universe with a recomputable rank,
\emph{is} the perfect hash filter of \Cref{def:phf}\index{perfect hash filter} at width $r = \lceil
\log_2 n \rceil$: zero false negatives, false positives at $2^{-r}$.
Renaming a fingerprint a rank changes nothing the query can observe.
\Cref{fig:phf-layout} shows the shared layout.

The perfect hash filter is not this chapter's invention.\index{fingerprint} The pairing of
a minimal perfect hash with $\lceil \log_2(1/\fprate) \rceil$-bit
fingerprints is the standard static approximate-membership construction,
described with its $\log_2 e$ overhead by
\textcite[Sec.~1]{dietzfelbinger-pagh-2008}, who note that its origin is
unknown to them; the program's manuscript \parencite{towell-bernoulli-phf}
restates it as a Bernoulli set and lifts it to maps.\index{Bernoulli set} It is the practical
FNR-zero construction, as against the salt-search BHF of
\Cref{def:bhf}: the BHF attains the floor $-\log_2 \fprate$ to leading
order but builds by exponential search, while the perfect hash filter
pays at least $\log_2 e \approx 1.44$ bits per element above the floor
(\Cref{prop:phf-space}) and builds in expected linear time by
off-the-shelf minimal perfect hashing. Because the overhead is additive,
it is a vanishing fraction of the cost as $\fprate \to 0$; at loose
targets it is not, and a Bloom filter can be smaller
(\Cref{sec:space-analysis}). The rank table of \Cref{def:bphf} is this
same construction read on the FPR-zero axis: it fixes $r = \lceil \log_2
n \rceil$ so that each slot can carry a distinct rank, and the witness
model of the next subsection turns the result into an exact filter.

This is the asymmetry \Cref{sec:bhf-to-bphf} promised. A false positive
is a coincidence, one stored value colliding with one recomputed value,
and a single $r$-bit slot makes it rare; a false-negative-free filter is
therefore cheap, bought for about $\log_2(1/\fprate)$ bits per element
plus the addressing. The FPR-zero axis asks the opposite, that no
non-member is ever accepted, and that is not a coincidence to make rare
but a certificate to enforce against every one of the $|\Universe| - n$
non-members at once. Certifying a subset exactly is the expensive
direction. The next two subsections give the two honest routes to it.

\subsection*{How the false-positive rate becomes zero}

The bare construction admits a non-member only when its recomputed rank
equals the rank stored at the slot it lands in. There is exactly one way
to close that gap without storing a universe's worth of information:
arrange the query so a non-member never presents a matching rank in the
first place. Call $\rho$ a \emph{witness} for $A$\index{witness model} when the recomputed
$\rho(x)$ equals the stored rank at slot $\phi(x)$ if and only if $x$ is
the member that claimed that slot. Under a witness, $R[\phi(x)] =
\rho(x)$ holds only for members, so
\[
  \fprate \;=\; 0
\]
holds exactly, by construction rather than in expectation. The relevance
ranking of a search corpus is the standard example, worked in
\Cref{sec:ranked-search}: a query is posed only for a document that
already carries its corpus rank, an outside document has no such rank to
present, and the witness condition is met.

The witness model is not a free upgrade. It restricts the query domain
to candidates that arrive with a verifiable rank, and it pays for the
guarantee in the only currency that buys it: the rank table stores, in
$n$ slots of $\lceil \log_2 n \rceil$ bits, enough to name every member
apart and certify a presented witness against the right slot. That is
the cost of certifying a subset exactly, the same counting argument that
set the book's earlier space bounds. A structure that accepts no
non-member must in effect encode which elements it accepts, and encoding
a designated subset of an arbitrary universe costs on the order of
$\log_2 n$ bits per element once the query domain is the corpus itself.
A genuinely universe-wide FPR-zero filter, rejecting every outsider by
recomputation alone, must distinguish $A$ among all $\binom{|\Universe|}{n}$
candidate sets and so stores about $\log_2(|\Universe|/n)$ bits per
element; at that price it is a dictionary, not a compact filter.

The witness model is a property of the query, not of the table, and the
distinction has teeth.

\begin{remark}[The FPR-zero guarantee lives in the query model]
\label{rem:witness-is-query-model}
The $\fprate = 0$ guarantee holds only when $\rho$ is a witness that
members possess and non-members cannot forge; it is not a property of the
stored table. A degenerate assignment, $\rho(a) = 0$ for all $a$, writes
zero into every slot, keeps $\fnrate = 0$, and admits every non-member
whose presented rank is zero, so the false-positive rate is the fraction
of queried non-members presenting zero. A low-entropy public $\rho$ an
adversary can evaluate on any candidate, such as a coarse document-length
bucket, is similarly forgeable: a non-member presents a rank matching its
slot with non-negligible probability. The guarantee survives only for a
$\rho$ that off-corpus candidates cannot recompute, a corpus sort
position or a salted hash of corpus-only metadata. \Cref{ch:not-bernoulli}
returns to the adversarial query in the broader catalogue, and the
keyed-witness construction is the bridge to the cipher maps of Part~V.
\end{remark}

With distinct ranks and a true perfect hash, the witness model places the
BPHF at the \emph{corner} of the perfect-filter line: both error rates
are zero on the query domain. The structure is exact there, and exactly
for that reason not yet an approximate set. The mirror of the perfect
hash filter, a tunable structure trading a controlled error for space,
comes from relaxing the perfect hash.

\subsection*{A controlled false-negative rate via k-perfect hashing}

The perfect hash filter moves along its axis by changing the fingerprint
width. The BPHF needs the matching dial on its own axis, a way to spend
less space for a controlled, nonzero $\fnrate$ while holding $\fprate =
0$. The dial is the perfect hash. A \emph{$k$-perfect
hash}\index{k-perfect hashing@$k$-perfect hashing} relaxes injectivity,
allowing up to $k$ members to share a slot; such hashes are standard
\parencite{belazzougui-2009}. A $k$-perfect hash into $m < n$ slots is
cheaper to store, but a shared slot holds only one member's rank; the
members that lose the contention read a different member's rank, fail
the comparison, and are reported as non-members. These displaced members
are the only error the $k$-perfect BPHF makes, and a non-member still
cannot present a witness, so $\fprate$ stays exactly zero. If the
construction occupies $o \le m$ slots, exactly $n - o$ members are
displaced, so
\begin{equation}
\label{eq:bphf-fnr}
  \fnrate \;=\; 1 - \frac{o}{n} \;\ge\; 1 - \frac{m}{n},
\end{equation}
with equality when every slot is occupied, zero at $m = n$ (the exact
corner), and growing as the table shrinks. A table at ninety percent of
full size, fully occupied, misses one member in ten while admitting no
non-member at all.

Three cautions keep the dial honest. First, the misses are not
independent across members: they are decided slot by slot, exactly one
of the members sharing a slot surviving, so the member side does not
satisfy element-wise independence (Axiom~1).\index{independence!across elements} The fraction $1 - o/n$ is a
property of the build, not a per-element coin. Second, a formula for the
expected number of displaced members under random placement must use the
same conditioning as the construction: a build that rejects placements
with an overfull slot has, for example, no displaced members at all when
$m = n = 2$ and $k = 1$, whereas the unconditional occupancy law gives
an expected displaced fraction of $1/4$. Third, in the fingerprint
reading of the same skeleton a displaced member is rescued whenever its
fingerprint happens to equal the slot owner's, so its false-negative rate
is the displaced fraction times $1 - 2^{-r}$; with one-bit fingerprints
and $k = 2$, a displacement probability of $1/4$ gives a membership
false-negative rate of $1/8$. Dropping members outright, as in the lossy
dictionaries\index{lossy dictionary} of \textcite{pagh-rodler-2001}, achieves a given $\fnrate$ in
fewer bits per retained member; the $k$-perfect variant buys construction
simplicity rather than space.

This is the mirror of the perfect hash filter made precise: the perfect
hash filter holds $\fnrate = 0$ and dials $\fprate$ down by adding
fingerprint bits; the BPHF holds $\fprate = 0$ in the witness model and
dials $\fnrate$ down by adding slots. Each lives on its own axis of
\Cref{def:perfect-filter-line}, paying for accuracy in space by
\Cref{prop:fpr-zero-closure}.

\subsection*{A worked example}

Fix $n = 1000$. The rank width is
\[
  r \;=\; \lceil \log_2 1000 \rceil \;=\; \lceil 9.966 \rceil \;=\; 10
  \text{ bits},
\]
since $2^{10} = 1024 \ge 1000 > 2^9 = 512$. The rank table occupies
$n r = 10{,}000$ bits ($1250$ bytes), plus a minimal perfect hash of at
least $\log_2 e \approx 1.44$ and in practice $2$ to $3.3$ bits per
element (\Cref{prop:phf-space}), for a total of roughly $11{,}500$ to
$13{,}300$ bits. At the corner, a true perfect hash with distinct ranks
in the witness model, $\fprate = \fnrate = 0$: the structure never
accepts a non-corpus candidate and never misses a corpus member, a
perfect-hash dictionary viewed as the corner of the line. To make it a
tunable approximate set, shrink to a $k$-perfect hash with $m = 900$
fully occupied slots. By \eqref{eq:bphf-fnr},
\[
  \fnrate \;=\; 1 - \tfrac{900}{1000} \;=\; 0.10,
  \qquad
  \fprate \;=\; 0,
\]
so one corpus member in ten is missed while no outside candidate is ever
accepted. For comparison, a perfect hash filter on the same set at
$\fprate = 0.01$ uses $r = 7$ bits per element for its table ($7000$
bits, plus the same perfect hash) and gives $\fnrate = 0$ at $\fprate
\le 0.0078$. The two answer opposite needs: the perfect hash filter never
misses a member and rarely admits a stranger; the BPHF never admits a
stranger and occasionally misses a member. An application that can
tolerate neither must pay the dictionary price for both.
\Cref{sec:ranked-search} works through one setting where the BPHF's
profile is exactly the one the problem wants.
